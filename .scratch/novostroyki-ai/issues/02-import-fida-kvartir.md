# 02 — Импорт квартир из XML/YML фида застройщика

**What to build:** Добавив ссылку на фид, система скачивает его, разбирает и складывает квартиры в базу — с ценой, площадью, этажом, комнатностью, планировкой и ссылкой на карточку. ЖК, которых ещё нет, создаются автоматически. Битый фид не роняет систему, а сохраняет понятную ошибку.

**Blocked by:** 01

**Status:** ready-for-agent

## Контекст

Спека: `docs/SPEC.md`, раздел «Синхронизация фидов».

Форматы: Яндекс.Недвижимость (YML-подобный `realty-feed`), ЦИАН XML, и `custom` — маппинг «путь в XML → поле квартиры» из JSON-конфига фида.

## Acceptance criteria

- [ ] Функция импорта принимает `feedId`, скачивает XML по ссылке, разбирает и делает upsert квартир по (`feedId`, `externalId`)
- [ ] Встроенные профили полей для форматов `yandex` и `cian` работают на эталонных фикстурах
- [ ] Формат `custom` берёт соответствие полей из `fieldMapping` фида
- [ ] ЖК создаётся автоматически по названию из фида, если не найден; повторный импорт не плодит дубли
- [ ] Квартиры, пропавшие из фида, помечаются `isActive = false` и не удаляются
- [ ] Цены и площади нормализуются: пробелы, запятые вместо точек, «млн» — приводятся к числу; `pricePerM2` считается, если его нет
- [ ] Комнатность нормализуется: студия → 0, «1-комнатная»/«1»/«1К» → 1
- [ ] Битый XML, недоступный URL и таймаут не выбрасывают исключение наружу — возвращается результат с текстом ошибки
- [ ] Квартиры без цены или без внешнего идентификатора пропускаются, их число попадает в результат импорта
- [ ] Результат импорта содержит: сколько добавлено, обновлено, деактивировано, пропущено
- [ ] Тесты на фикстурах: корректный фид Яндекса, корректный ЦИАН, фид с битым XML, фид с пропущенными полями, повторный импорт (идемпотентность), исчезнувшая квартира
