# 04 — База знаний: загрузка документов и поиск по ним

**What to build:** Загрузив PDF-презентацию застройщика, человек делает её знанием ассистента. Текст извлекается, режется на фрагменты и индексируется. Поиск по-русски находит нужный фрагмент с учётом морфологии — запрос «ипотека» находит «ипотечную программу». Документ можно привязать к конкретному ЖК, чтобы условия одного проекта не приписывались другому.

**Blocked by:** 01

**Status:** ready-for-agent

## Контекст

Спека: `docs/SPEC.md`, раздел «Поиск по базе знаний».

Векторные эмбеддинги не используются — только полнотекстовый поиск PostgreSQL с конфигурацией `russian` плюс `pg_trgm` для устойчивости к опечаткам в названиях ЖК.

## Acceptance criteria

- [ ] `POST /api/admin/knowledge` принимает файл (PDF, DOCX, TXT, MD) и необязательный `projectId`
- [ ] Текст извлекается: PDF через `pdf-parse`, DOCX через `mammoth`, TXT/MD как есть
- [ ] Текст режется на фрагменты по абзацам с укрупнением до ~900 символов и перекрытием ~150; фрагменты не рвутся посреди слова
- [ ] Для каждого фрагмента считается `tsv` с конфигурацией `russian`
- [ ] Функция поиска принимает запрос и необязательный `projectId`, возвращает до 6 фрагментов, отсортированных по релевантности, с названием документа и ЖК
- [ ] Поиск находит с учётом русской морфологии: «ипотека» находит «ипотечный», «сдача» находит «сдаётся»
- [ ] Поиск с указанным `projectId` возвращает фрагменты этого ЖК и общие (без привязки), но не фрагменты чужих ЖК
- [ ] Удаление документа удаляет его фрагменты, они пропадают из выдачи
- [ ] Файл, из которого не удалось извлечь текст, получает статус ошибки с понятным текстом и не ломает загрузку остальных
- [ ] Ограничение размера файла (20 МБ) с внятной ошибкой при превышении
- [ ] Тесты: извлечение из каждого формата, чанкинг на длинном тексте, морфологический поиск, изоляция по ЖК, удаление документа, битый файл
