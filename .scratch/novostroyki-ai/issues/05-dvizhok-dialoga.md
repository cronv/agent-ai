# 05 — Движок диалога: Claude с инструментами подбора

**What to build:** Ассистент понимает запрос в свободной форме, сам решает, что ему нужно — найти квартиры, посмотреть список ЖК или заглянуть в базу знаний — вызывает нужный инструмент и отвечает по фактам из базы, а не из головы. Вся переписка сохраняется, включая то, какие именно квартиры были показаны.

**Blocked by:** 02, 04

**Status:** ready-for-agent

## Контекст

Спека: `docs/SPEC.md`, разделы «Модель» и «Инструменты модели (tool use)».

Модель — Anthropic Claude. `claude-haiku-4-5-20251001` по умолчанию, `claude-sonnet-5` на сложные запросы (сравнение ЖК, многокритериальный подбор, вопросы к базе знаний). Ключ берётся из настроек в БД, фолбэк — переменная окружения `ANTHROPIC_API_KEY`.

**Обязательно:** перед реализацией прочитать навык `claude-api` — там актуальные идентификаторы моделей, форматы tool use и стриминга. Не писать интеграцию по памяти.

Данные квартир возвращаются модели через результат инструмента и **одновременно** сохраняются в сообщение структурно — виджет рендерит карточки из этих данных, а не парсит текст ответа.

## Acceptance criteria

- [ ] Реализованы четыре инструмента со схемами из спеки: `search_apartments`, `list_projects`, `search_knowledge`, `save_lead`
- [ ] `search_apartments` фильтрует по комнатам, цене, площади, этажу, ЖК, району, метро, сроку сдачи, отделке; возвращает только активные квартиры активных ЖК; лимит по умолчанию 5
- [ ] `list_projects` возвращает ЖК с диапазоном цен и количеством доступных лотов
- [ ] `search_knowledge` ходит в поиск из тикета 04 и возвращает фрагменты с указанием источника
- [ ] Цикл tool use отрабатывает несколько итераций подряд, ограничение — 5 вызовов инструментов на одно сообщение
- [ ] Системный промпт берётся из настроек; в нём заданы правила: не выдумывать цены и сроки, при отсутствии данных предлагать связаться с менеджером, не просить контакт раньше подборки и уточняющего вопроса
- [ ] Выбор модели: Haiku по умолчанию, эскалация на Sonnet по признакам сложного запроса; выбранная модель пишется в сообщение
- [ ] Каждое сообщение сохраняется с ролью, текстом, вызовами инструментов, показанными квартирами и расходом токенов; у диалога обновляются счётчики
- [ ] История диалога передаётся модели с ограничением по длине — старые сообщения обрезаются, не ломая пары «вызов инструмента → результат»
- [ ] Ошибка или недоступность API модели даёт понятное сообщение пользователю и запись в лог, а не падение
- [ ] Тесты с мок-клиентом Anthropic, без реальных HTTP-запросов: вызов инструмента с правильными параметрами, возврат результата модели, сохранение структурных данных квартир в сообщение, обрезка длинной истории, поведение при ошибке API
