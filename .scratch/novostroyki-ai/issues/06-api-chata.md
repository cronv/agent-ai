# 06 — API чата: сессии, стриминг ответа, история

**What to build:** Виджет на сайте может вести диалог: отправляет сообщение и получает ответ по мере генерации, слово за словом, а не одним куском через десять секунд. Вернувшись на сайт позже, посетитель видит свою прошлую переписку. Вместе с диалогом сохраняется, с какой страницы и по какой рекламной метке пришёл человек.

**Blocked by:** 05

**Status:** ready-for-agent

## Контекст

Спека: `docs/SPEC.md`, раздел «Виджет». Стриминг — Server-Sent Events. `sessionId` генерирует клиент и хранит в `localStorage`.

## Acceptance criteria

- [ ] `POST /api/chat` принимает `sessionId`, текст сообщения и контекст страницы (`pageUrl`, `referrer`, `utm`), отвечает потоком SSE
- [ ] В потоке идут события: куски текста, показанные квартиры структурно, признак завершения, признак ошибки
- [ ] Диалог создаётся при первом сообщении сессии; повторные сообщения пишутся в тот же диалог
- [ ] UTM-метки и страница входа сохраняются один раз при создании диалога и не перетираются
- [ ] `GET /api/chat/:sessionId` возвращает историю сообщений для восстановления переписки
- [ ] `GET /api/widget/config` отдаёт публичные настройки виджета: название, акцентный цвет, приветствие, примеры вопросов
- [ ] CORS настроен так, чтобы виджет работал с внешнего домена
- [ ] Ограничение частоты запросов по сессии и по IP — защита от накрутки расхода токенов
- [ ] Обрыв соединения клиентом не оставляет висящих запросов к модели
- [ ] Тесты: полный цикл сообщения с мок-моделью, создание и переиспользование диалога, сохранение UTM, восстановление истории, срабатывание лимита частоты
