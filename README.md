# AI-ассистент по новостройкам

Чат-помощник для сайта агентства недвижимости. Посетитель пишет своими словами
(«двушка до 18 миллионов рядом с метро, сдача до 2027»), ассистент подбирает
конкретные квартиры из выгрузок застройщиков, отвечает на вопросы по загруженным
презентациям и в подходящий момент просит контакт. Всё видно в админке:
переписки, лиды, состояние выгрузок, база знаний, настройки.

Полное описание задуманного — в `docs/SPEC.md`.

---

## Что уже готово

Это первый шаг: собран каркас, база данных и запуск одной командой.
Чат, админка и загрузка выгрузок делаются следующими задачами.

Прямо сейчас работает:

- запуск всего проекта одной командой;
- база данных со всеми таблицами;
- проверка здоровья сервиса;
- заготовки админки и виджета — открываются, но пока пустые.

---

## Что нужно установить

Одна программа — **Docker Desktop** (https://www.docker.com/products/docker-desktop).
Больше ничего ставить не надо: Node.js, база данных и всё остальное живут внутри Docker.

Установили — запустите Docker Desktop и дождитесь, пока значок кита перестанет
мигать. Всё, можно продолжать.

---

## Запуск

Откройте терминал в папке проекта и выполните:

```bash
docker compose up
```

Первый запуск занимает 2–3 минуты: скачиваются образы и собирается проект.
Когда в терминале появится строчка `Server listening`, откройте в браузере:

**http://localhost:3000**

Вы увидите страницу с надписью «сервис работает» и ссылками:

| Адрес | Что там |
|---|---|
| http://localhost:3000 | стартовая страница |
| http://localhost:3000/admin | админка |
| http://localhost:3000/api/health | ответ `{"status":"ok","db":"ok"}` — сервис и база на связи |
| http://localhost:3000/widget.js | файл виджета для вставки на сайт |

Чтобы остановить — нажмите `Ctrl+C` в терминале.

Чтобы запустить в фоне и не занимать терминал:

```bash
docker compose up -d      # запустить
docker compose logs -f    # смотреть, что происходит
docker compose down       # остановить
```

### Если порт 3000 занят

Скопируйте `.env.example` в `.env` и поменяйте в нём `APP_PORT` на свободный,
например `APP_PORT=3100`. После этого проект откроется по адресу
http://localhost:3100.

## Настройки

Все настройки лежат в файле `.env` в корне проекта. Его нет сразу после
скачивания — создайте копией примера:

```bash
cp .env.example .env
```

Внутри всё подписано по-русски. Самое важное:

| Переменная | Зачем |
|---|---|
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | логин и пароль от админки — **обязательно поменяйте перед выкладкой на сервер** |
| `SESSION_SECRET` | случайная строка для защиты сессии — тоже поменяйте на сервере |
| `ANTHROPIC_API_KEY` | ключ доступа к Claude; можно оставить пустым и вставить позже через админку |
| `APP_PORT` | на каком порту открывать проект в браузере |

Настройки самого ассистента — характер, приветствие, цвет виджета, ключ
Anthropic, адрес вебхука, расписание обновления выгрузок — задаются в админке
и хранятся в базе. В `.env` их дублировать не нужно.

## Автотесты

Тесты работают против настоящего PostgreSQL в Docker, а не против подделки:
проверяются полнотекстовый поиск по-русски, уникальные индексы и колонка
`tsvector` — на подменённой базе это проверить невозможно.

Запуск (Docker должен быть запущен):

```bash
npm install   # один раз
npm test
```

Тестовая база поднимается автоматически, миграции накатываются сами, данные
между тестами вычищаются. Основную базу тесты не трогают — она отдельная,
на порту 5434, и живёт в памяти.

Поднять тестовую базу отдельно, если нужно:

```bash
npm run db:test:up     # поднять
npm run db:test:down   # убрать
```

## Разработка без Docker

Так сервер перезапускается сам при изменении кода.

```bash
npm install            # один раз
npm run db:up          # поднять только базу данных в Docker
npm run migrate:deploy # накатить миграции
npm run build          # собрать админку и виджет (один раз)
npm run dev            # запустить сервер, порт 3000
```

Админку удобнее править отдельной командой — она подхватывает изменения
мгновенно и сама ходит на сервер за данными:

```bash
npm run dev:admin      # http://localhost:5173/admin/
```

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер с автоперезапуском |
| `npm run dev:admin` | админка в режиме разработки |
| `npm run dev:widget` | виджет в режиме разработки |
| `npm run build` | собрать всё: виджет, админку, сервер |
| `npm start` | запустить собранный сервер |
| `npm test` | автотесты |
| `npm run typecheck` | проверка типов во всех пакетах |
| `npm run migrate:dev` | создать новую миграцию после правки схемы |
| `npm run migrate:deploy` | накатить миграции |
| `npm run prisma:generate` | пересобрать клиент базы данных после правки схемы |
| `npm run db:up` / `npm run db:down` | поднять / остановить базу в Docker |
| `npm run db:test:up` / `npm run db:test:down` | то же для тестовой базы |

## Как устроен проект

```
.
├── docker-compose.yml        запуск: база + приложение
├── Dockerfile                сборка приложения
├── .env.example              все переменные с пояснениями
├── docs/SPEC.md              спецификация
└── packages/
    ├── server/               сервер: API, база, движок диалога
    │   ├── prisma/
    │   │   ├── schema.prisma      описание таблиц
    │   │   └── migrations/        история изменений базы
    │   └── src/
    │       ├── app.ts             сборка HTTP-приложения
    │       ├── index.ts           точка входа
    │       ├── config/            переменные окружения и пути
    │       ├── db/                доступ к базе данных
    │       ├── lib/               общие мелочи
    │       ├── plugins/           общие зависимости и раздача статики
    │       ├── routes/            HTTP-маршруты
    │       ├── services/          прикладная логика (настройки и далее)
    │       └── testing/           обвязка для тестов
    ├── admin/                админка: React + Vite + Tailwind
    └── widget/               виджет для сайта: Preact, один файл widget.js
```

Три пакета живут в одном репозитории (npm workspaces). `npm install` в корне
ставит зависимости сразу для всех.

### База данных

PostgreSQL 16, схема описана в `packages/server/prisma/schema.prisma`.
Таблицы: ЖК, выгрузки, квартиры, документы базы знаний и их фрагменты,
переписки, сообщения, лиды, настройки.

Поиск по базе знаний — встроенный полнотекстовый поиск PostgreSQL с русской
морфологией. У фрагментов есть колонка `tsv` типа `tsvector`; она заполняется
автоматически триггером и покрыта GIN-индексом. Расширения `pg_trgm`
(устойчивость к опечаткам) и `unaccent` включаются миграцией.

Миграции применяются сами при каждом запуске `docker compose up` —
отдельных шагов не требуется.

## Вставка виджета на сайт

Одна строчка перед закрывающим тегом `</body>`:

```html
<script src="http://localhost:3000/widget.js" defer></script>
```

При выкладке на сервер замените `http://localhost:3000` на адрес вашего сайта.
Готовую строчку с правильным адресом покажет админка.

## Что нужно от вас

Проект собирается и запускается без этого — всё вставляется позже через админку:

1. Ссылки на XML/YML-выгрузки застройщиков.
2. Ключ доступа к Claude (`ANTHROPIC_API_KEY`).
3. Доступ к серверу для выкладки (локально всё работает и без него).
4. Файлы базы знаний: презентации, условия ипотеки, описания ЖК.
5. Название агентства и акцентный цвет виджета.
6. Ссылка на политику обработки персональных данных — она показывается
   в чекбоксе согласия рядом с формой контакта.

## Если что-то не работает

**«Cannot connect to the Docker daemon»** — не запущен Docker Desktop.
Запустите его и подождите, пока значок кита перестанет мигать.

**«port is already allocated»** — порт занят другой программой.
Поменяйте `APP_PORT` или `POSTGRES_PORT` в файле `.env`.

**Страница не открывается сразу после `docker compose up`** — первый запуск
занимает пару минут. Дождитесь строчки `Server listening` в терминале.

**Начать с чистого листа** (удалит все данные из базы):

```bash
docker compose down -v
docker compose up --build
```
