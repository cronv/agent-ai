# Спецификация: AI-ассистент по новостройкам

Статус: утверждена (грилинг пройден, 8 вопросов)
Дата: 2026-07-27

---

## Problem Statement

Агентство-агрегатор новостроек продаёт квартиры десятков застройщиков. Посетитель сайта не может сам сориентироваться: объектов много, фильтры на сайте примитивные, а ключевые для решения вещи — сроки сдачи, отделка, ипотечные программы, рассрочка — лежат в PDF-презентациях, которых на сайте нет вовсе.

В итоге:

- Посетитель уходит, не найдя подходящую квартиру, хотя она есть в базе.
- Вопросы «а есть ли субсидированная ипотека» остаются без ответа до звонка менеджера.
- Менеджер тратит первые 10 минут разговора на выяснение того, что клиент уже знал сам.
- Часть трафика не оставляет контакт вообще: форма «оставьте заявку» появляется раньше, чем возник интерес.

## Solution

Виджет-ассистент в правом нижнем углу сайта. Ведёт диалог на русском, понимает запрос в свободной форме («двушка до 18 миллионов рядом с метро, сдача до 2027»), подбирает конкретные квартиры из фидов застройщиков, показывает планировку и ссылку на карточку, отвечает на вопросы по проектам из загруженной базы знаний и в подходящий момент диалога просит контакт для звонка.

Всё, что происходит, видно в админке: переписки целиком, лиды с историей просмотров, состояние фидов, база знаний, настройки.

## Implementation Decisions

### Общая архитектура

Монорепозиторий, три пакета:

- **server** — Node.js + TypeScript, Fastify. HTTP API, движок диалога, синхронизация фидов, разбор документов. Отдаёт статику админки и бандл виджета.
- **admin** — React + Vite + Tailwind. SPA админки.
- **widget** — Preact + Vite, собирается в один самодостаточный `widget.js`. Монтируется в Shadow DOM.

Разворачивается через Docker Compose: два сервиса — `postgres` и `app`. Имя compose-проекта задаётся явно (`name: novostroyki-ai`), потому что путь к каталогу содержит пробел и кириллицу.

### Модель

Anthropic Claude. `claude-haiku-4-5-20251001` — основная модель диалога. `claude-sonnet-5` — эскалация на сложные запросы (сравнение проектов, многокритериальный подбор, вопросы по базе знаний). Выбор модели — по признакам запроса, определяется на сервере, настраивается в админке.

Ключ хранится в настройках БД (вводится в админке) с фолбэком на переменную окружения `ANTHROPIC_API_KEY`.

### Инструменты модели (tool use)

Диалог построен на tool use, не на подстановке данных в промпт. Инструменты:

- `search_apartments` — параметры: `rooms[]`, `price_min`, `price_max`, `area_min`, `area_max`, `floor_min`, `floor_max`, `project_ids[]`, `district`, `metro`, `deadline_before`, `finishing`, `limit`. Возвращает массив квартир со всеми полями карточки. Только активные квартиры активных ЖК.
- `list_projects` — параметры: `district`, `metro`, `price_min`, `price_max`, `deadline_before`. Возвращает ЖК с диапазоном цен и количеством лотов. Нужен для запросов «какие есть проекты в …».

`district` в обоих инструментах сравнивается не буквально: человек пишет «Домодедово», а в базе может стоять «Домодедовский городской округ» и наоборот. Название места переводится в список ЖК триграммным поиском `pg_trgm` по колонке `district`, а если там ничего не нашлось — по названию и адресу ЖК. Пустой результат означает «такого места в каталоге нет».
- `search_knowledge` — параметры: `query`, `project_id?`. Полнотекстовый поиск по чанкам, возвращает до 6 фрагментов с указанием документа и ЖК.
- `save_lead` — параметры: `name`, `phone`, `comment?`. Вызывается только после явного согласия пользователя.

Результаты `search_apartments` и `list_projects` сохраняются в сообщение структурно — виджет рендерит из них карточки, а не парсит текст модели.

### Схема данных (PostgreSQL, Prisma)

- `Project` — ЖК: `name`, `slug`, `developer`, `district`, `metro`, `metroDistanceMin`, `address`, `deadline`, `finishing`, `description`, `url`, `imageUrl`, `isActive`.
- `Feed` — источник: `name`, `url`, `format` (`yandex` | `cian` | `domclick` | `custom`), `fieldMapping` (JSON), `scheduleCron`, `isActive`, `lastRunAt`, `lastStatus`, `lastError`, `lastCount`.
- `Apartment` — лот: `feedId`, `projectId`, `externalId`, `rooms`, `area`, `livingArea`, `kitchenArea`, `floor`, `floorsTotal`, `price`, `pricePerM2`, `building`, `section`, `finishing`, `deadline`, `planImageUrl`, `url`, `isActive`, `raw` (JSON), `syncedAt`. Уникальность по (`feedId`, `externalId`).
- `KnowledgeDoc` — документ: `projectId?`, `filename`, `mimeType`, `sizeBytes`, `charCount`, `status`, `error`, `createdAt`.
- `KnowledgeChunk` — фрагмент: `docId`, `projectId?`, `content`, `position`, `tsv` (tsvector, GIN-индекс).
- `Conversation` — диалог: `sessionId`, `pageUrl`, `referrer`, `utm` (JSON), `userAgent`, `startedAt`, `lastMessageAt`, `messageCount`, `tokensIn`, `tokensOut`.
- `Message` — сообщение: `conversationId`, `role` (`user` | `assistant`), `content`, `apartments` (JSON — что показали), `toolCalls` (JSON), `model`, `createdAt`.
- `Lead` — контакт: `conversationId`, `name`, `phone`, `comment`, `status` (`new` | `in_progress` | `reached` | `rejected`), `consentAt`, `createdAt`.
- `Setting` — ключ-значение: системный промпт, приветствие, примеры вопросов, акцентный цвет, название, ключ Anthropic, адрес вебхука, порог запроса контакта, cron синхронизации.

### Поиск по базе знаний

Полнотекстовый поиск PostgreSQL с конфигурацией `russian`, без векторных эмбеддингов. Причина: у Anthropic нет embeddings API, второй платный ключ не заводим. `tsvector` считается при вставке чанка, ранжирование `ts_rank_cd`, дополнительно `pg_trgm` для устойчивости к опечаткам в названиях ЖК.

Чанкинг: разбивка по абзацам с укрупнением до ~900 символов и перекрытием ~150. Извлечение текста: `pdf-parse` для PDF, `mammoth` для DOCX, чтение как есть для TXT/MD.

### Синхронизация фидов

`node-cron` внутри процесса приложения, расписание из настроек (по умолчанию каждые 3 часа). Разбор XML — `fast-xml-parser`. Встроенные профили полей для Яндекс.Недвижимости, ЦИАН и ДомКлик; для `custom` — маппинг «путь в XML → поле квартиры», задаётся в админке. В выгрузке ДомКлик данные лота разбросаны по уровням `complex → building → flat`, поэтому её профиль задаёт собственный обход документа, а не словарь путей.

Отдельного поля с районом ДомКлик не отдаёт: он вычисляется из адреса комплекса (часть до первой точки) и уточнения в скобках названия, приводится к человеческой форме — «Домодедовский городской округ» → «Домодедово».

Импорт — upsert по (`feedId`, `externalId`). Лоты, пропавшие из фида, помечаются `isActive = false`, не удаляются (нужны для истории переписок). ЖК создаётся автоматически по названию из фида, если не найден; дальше редактируется руками. Заполненные поля ЖК импорт не трогает — правки администратора важнее фида, — но пустые дозаполняет, чтобы новое поле в разборе доезжало до каталога само.

### Запрос контакта

Ассистент просит контакт по правилу в системном промпте: не раньше, чем пользователь увидел подборку и задал хотя бы один уточняющий вопрос. Порог настраивается. Форма контакта рендерится виджетом как отдельный блок в ленте чата: имя, телефон с маской `+7 (___) ___-__-__`, чекбокс согласия на обработку персональных данных со ссылкой на политику. Без чекбокса кнопка неактивна.

После сохранения лида — вызов вебхука, если адрес задан в настройках. Формат payload совместим с существующим amo-воркером пользователя: `{ name, phone, lead_name, comment, meta: { page, referrer, utm } }`. Ошибка вебхука не роняет сохранение лида и пишется в лог.

### Виджет

Один файл `widget.js`, подключается строчкой `<script src="https://.../widget.js" data-key="..." defer></script>`. Монтируется в Shadow DOM — стили сайта не протекают внутрь и наоборот. Светлый минимализм: белый фон, воздух, один акцентный цвет из настроек, крупная типографика, карточки квартир с превью планировки. Ответы стримятся по SSE. Мобильная версия — на всю высоту экрана.

`sessionId` хранится в `localStorage`, при возврате история подгружается.

### Админка

React SPA под `/admin`. Авторизация — логин/пароль из переменных окружения, сессия в httpOnly-куке (JWT). Разделы: Дашборд, ЖК, Фиды, База знаний, Переписки, Лиды, Настройки.

## Testing Decisions

Хороший тест здесь проверяет внешнее поведение модуля, а не его внутренности. Тестируются швы, а не функции.

Vitest. Три группы:

1. **Чистая логика, без БД** — разбор фида (эталонные XML-файлы Яндекса, ЦИАН и ДомКлик в фикстурах, включая битые), маппинг полей, нормализация цен и площадей, чанкинг текста, определение момента запроса контакта, выбор модели по запросу.
2. **API поверх реальной БД** — `fastify.inject` против тестовой базы в Docker, миграции и очистка между тестами. Проверяются: полный цикл импорта фида, поиск квартир по всем комбинациям фильтров, поиск по базе знаний с русской морфологией, сохранение лида с вебхуком (мок), авторизация админки (401 без куки).
3. **Движок диалога с мок-клиентом Anthropic** — реальные HTTP-запросы к модели не делаются. Проверяется, что при заданном ответе модели с tool call инструмент вызывается с правильными параметрами, результат возвращается модели, а структурные данные квартир попадают в сообщение.

Единственный внешний сервис, который мокается — Anthropic. Postgres в тестах настоящий.

## Out of Scope

- Интеграции с CRM из коробки. Только исходящий вебхук.
- Голосовые звонки, WhatsApp, Telegram как каналы диалога. Только виджет на сайте.
- Онлайн-бронирование и оплата.
- Мультиязычность. Только русский.
- Личный кабинет застройщика.
- Векторный поиск и эмбеддинги.
- Мультитенантность / SaaS-биллинг.
- Мобильные приложения.
- A/B-тесты промптов.

Соберётся и запустится без этого, вводится в админке после развёртывания:

1. `PLACEHOLDER — ссылки на XML/YML фиды застройщиков`

3. `PLACEHOLDER — доступ к VPS для деплоя` (локальный запуск работает сразу)
4. `PLACEHOLDER — файлы базы знаний: презентации, условия ипотеки`
5. `PLACEHOLDER — название агентства и акцентный цвет`
6. `PLACEHOLDER — ссылка на политику обработки персональных данных` (в чекбоксе согласия)

Для демонстрации до появления реальных данных проект содержит демо-фид на 30 квартир в 4 ЖК и демо-документ базы знаний.

### Принятые технические решения, не требовавшие решения пользователя

- Хостинг: VPS в РФ. Персональные данные не покидают РФ — 152-ФЗ.
- Поиск по знаниям: PostgreSQL FTS вместо эмбеддингов.
- Модель: Haiku 4.5 по умолчанию, Sonnet 5 на эскалацию.
- Лиды: только админка, плюс пустое поле вебхука на будущее.

### Замечание, переданное пользователю

Скорость первого звонка в новостройках решает больше, чем что-либо ещё. Лиды только в админке означают, что кто-то должен её открывать. Поле вебхука позволяет подключить Telegram-уведомления за 10 минут, без изменений кода.
