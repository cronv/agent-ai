# Шлюз к Claude на Cloudflare

Anthropic обслуживает не все страны, и **России в их списке нет**. Запрос с
российского адреса получает отказ `403` ещё до проверки ключа — поэтому
исправный ключ выглядит сломанным. Шлюз решает ровно это: приложение и база
с телефонами клиентов остаются в России, а наружу через Cloudflare уходит
только сам вопрос к модели.

Настройка занимает минут десять. Ничего устанавливать на компьютер не нужно —
всё делается на сайте Cloudflare. Программистом быть не требуется.

---

## Шаг 1. Завести аккаунт Cloudflare

[dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) — бесплатно,
карта не нужна. Бесплатного тарифа хватает с огромным запасом: он даёт
100 000 запросов в сутки, а у нас их сотни.

## Шаг 2. Создать воркер

1. В меню слева — **Compute (Workers)** → **Workers & Pages**
2. Кнопка **Create** → **Start with Hello World!** → **Get started**
3. Придумайте имя, например `ndv-claude-gate`
4. **Deploy**

Cloudflare покажет адрес вида `https://ndv-claude-gate.ваш-логин.workers.dev`.
**Запишите его** — он понадобится на шаге 6.

## Шаг 3. Вставить код

1. На странице воркера — **Edit code** (или **</> Edit Code** справа вверху)
2. Выделите весь код в редакторе и удалите
3. Откройте файл [`src/worker.js`](src/worker.js), скопируйте целиком и вставьте
4. **Deploy** справа вверху

## Шаг 4. Задать пароль шлюза

Без пароля адрес шлюза стал бы открытым ретранслятором: его находят перебором
за часы и начинают гонять через него чужой трафик. Поэтому пароль обязателен —
без него шлюз намеренно отказывается работать вовсе.

1. Вкладка **Settings** → раздел **Variables and Secrets** → **Add**
2. Type: **Secret**  ·  Name: `GATEWAY_TOKEN`
3. Value — длинная случайная строка. Можно взять эту:

   ```
   -VpIDTJxQ2HwJiC4L2y54q8L02peoU2n
   ```

4. **Deploy**

Пароль станет частью адреса, по которому приложение ходит в Claude. Никому
его не показывайте.

## Шаг 5. Включить Smart Placement

Это важный шаг, и его легко пропустить. По умолчанию Cloudflare запускает
воркер рядом с тем, кто его вызвал, — то есть в России, а тогда до Anthropic
запрос снова пойдёт с российского адреса и снова получит отказ. Smart Placement
переносит выполнение ближе к Anthropic.

**Settings** → **Placement** → выбрать **Smart** → сохранить.

## Шаг 6. Проверить, что шлюз работает

Откройте в браузере адрес воркера, добавив к нему пароль и `/whoami`:

```
https://ndv-claude-gate.ваш-логин.workers.dev/-VpIDTJxQ2HwJiC4L2y54q8L02peoU2n/whoami
```

Шлюз сам сходит в Anthropic и честно скажет, принимают его оттуда или нет:

| Что написано | Что это значит |
| --- | --- |
| `РАБОТАЕТ` | Anthropic принимает запросы через шлюз. Переходите к шагу 7. |
| `НЕ РАБОТАЕТ` | Отказ по региону сохранился. Проверьте, что шаг 5 выполнен, и откройте страницу ещё раз. |
| `Шлюз не настроен` | Не задан `GATEWAY_TOKEN` — вернитесь к шагу 4. |
| `Не найдено` | Пароль в адресе не совпадает с тем, что в настройках воркера. |

Проверка не гадает по стране IP-адреса — она делает настоящий запрос к Anthropic
с заведомо негодным ключом и смотрит на ответ. `401` значит «регион приняли, ключ
выдуман» — это и есть успех. `403` значит «отказ по региону».

## Шаг 7. Подключить шлюз к приложению

В админке: **Настройки** → **Ключи и интеграции** → поле **«Адрес доступа
к Claude»**. Вставьте адрес воркера вместе с паролем, **без** `/whoami`:

```
https://ndv-claude-gate.ваш-логин.workers.dev/-VpIDTJxQ2HwJiC4L2y54q8L02peoU2n
```

Сохраните и нажмите **«Проверить ключ»**. Должно ответить, что ключ работает.
Перезапускать сервер не нужно — адрес читается на каждом запросе.

То же значение можно задать переменной окружения `ANTHROPIC_BASE_URL`, если
удобнее менять настройки на сервере, а не в админке.

---

## Что стоит знать

**Cloudflare видит переписки в момент передачи.** Шифрование до него и после
него разное, значит содержимое запроса и ключ Anthropic проходят через их
серверы открытыми. Это цена любого шлюза, не только этого. Само хранение
переписок и телефонов при этом остаётся в России — из базы наружу ничего не
уезжает.

**Ключ Anthropic не хранится в Cloudflare.** Он лежит в базе приложения и
подставляется в каждый запрос; шлюз просто передаёт его дальше, не читая.

**Если шлюз откажет,** чат покажет посетителю «Чат сейчас не отвечает» и
предложит оставить телефон. Заявки продолжат собираться, подбор квартир
через админку тоже работает — без модели остаётся только диалог.

## Для тех, кто предпочитает командную строку

Вместо шагов 2–5 можно развернуть воркер из этой папки:

```bash
npx wrangler deploy                      # создаст воркер по wrangler.toml
npx wrangler secret put GATEWAY_TOKEN    # спросит пароль
```

`wrangler.toml` рядом уже включает Smart Placement.

## Тесты

```bash
npm test --workspace @novostroyki/gateway
```

Cloudflare для них не нужен: `handle` принимает `fetch` отдельным аргументом,
и в тестах подменяется именно он. Проверяется то, на чём такие шлюзы обычно и
ломаются, — сборка адреса, отсев служебных заголовков Cloudflare и то, что
ответ модели идёт потоком, а не копится целиком.
